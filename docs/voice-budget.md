# 行为规格（声部预算与 64 轨）

这些约定同时被单元测试与界面使用，改动前请先确认对应测试。

## 轨道

- 上限 `MAX_TRACKS = 64`；旧存档的 8 轨上限不再生效。
- 每条轨道有 `priority` 1–9（默认 5）。旧存档缺省为 5，听感与旧版一致。
- 静音、删除、清空都以**轨道 id** 为准，与当前可见行、滚动位置无关。

## 声部预算（`VOICE_BUDGET`）

- 预算是「同时发声的合成声部数」，不是轨道数。64 条轨道可以全部参与调度，
  真正限制的是同一时刻的振荡器/噪声源数量。
- 一次调度内，同一条轨道、同一时刻触发的全部音符构成一个**原子声部组**。
  预算只会整组接受或整组拒绝：绝不存在「和弦只响一半」。
- 优先级顺序（从高到低）：
  1. 正在现场按住 / 正在录音的声音 —— 永不因预算被掐；
  2. 回放声部按轨道 `priority` 从高到低；
  3. 同优先级时，编排中靠前的轨道优先。
- 回放申请需要腾位时：
  - 只淘汰「优先级更低」或「同优先级但轨道更靠后」的回放声部；
  - 若淘汰候选不足以腾出空间，则**整组拒绝**，不会先掐掉别的声音再失败；
  - 现场声音的申请即使腾不出空间也照常发声（短暂超额优于掐掉手指下的音）。
- 记账按时间区间重叠计算：预排的未来音符不会挤掉当前正在响的和弦。
- 静音 / 删轨 / 清空会立即停止该轨道正在发声的声部并归还名额。
- 保存与提交从不参考预算：大作品完整保存全部音符。

## 界面

- 编排与混音台都使用固定行高虚拟滚动：滚出屏幕的轨道不渲染 DOM，
  但仍在模型中参与播放与录音。
- 混音推子、静音按钮绑定真实轨道 id 与真实混音总线，不随可见行漂移。
- 录音目标在 `arm` 时固定为轨道 id；滚动或切轨不会改变它。
- 受限轨道在编排行、混音条与底部状态栏都有可见标记，并给出原因
  （`evicted` 已让位 / `rejected` 整组未排入）。

## 资源生命周期

- 每个声部在结束时间后由 `sweep` 归还；反复播放、滚动、暂停恢复不累积节点。
- 混音总线在删轨时断开；换 AudioContext 时旧节点全部断开。
